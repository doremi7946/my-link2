# `/{displayName}` 동적 라우팅 페이지 구현 계획

## 1. 개요
각 유저가 생성한 링크 목록을 다른 사람들에게 공유할 수 있는 공개 프로필 페이지(`/{displayName}`)를 생성합니다. 사용자가 로그인 후 본인의 링크를 관리하는 페이지(`app/links/page.tsx`) 외에, 외부 방문자가 접속하여 링크를 확인할 수 있는 읽기 전용(Read-only)의 미려한 페이지를 구성합니다.

## 2. 세부 설계 및 요구사항
- **동적 라우팅 경로**: 
  - `app/[displayName]/page.tsx` 경로에 페이지를 작성합니다.
  - 사용자가 `@Jeongwoo`와 같이 `@` 기호를 붙여 접속하는 경우와 `Jeongwoo`로 접속하는 경우 모두 대응할 수 있도록 파라미터 맨 앞의 `@`는 제거하여 유저를 검색합니다.
- **유저 및 링크 조회**:
  - `lib/firestore-service.ts`에 `fetchProfileByDisplayName(displayName)` 함수를 신설합니다.
  - Firestore의 `users` 컬렉션에서 `displayname` 필드가 일치하는 유저 문서를 검색하고, 만약 일치하는 이름이 없으면 `handle` 필드로 재검색합니다.
  - 유저 문서가 확인되면 해당 문서의 `uid`를 이용하여 `users/{uid}/links` 경로의 링크 데이터를 조회합니다.
- **404 예외 처리**:
  - 만약 해당하는 유저가 존재하지 않는 경우 Next.js의 `notFound()` 함수를 사용하여 404 페이지로 리다이렉트합니다.
  - 이를 위해 `app/not-found.tsx`에 아름다운 디자인의 커스텀 404 에러 페이지를 제공합니다.
- **공개 프로필 페이지 디자인**:
  - 비로그인 외부 방문자용 페이지이므로 수정, 삭제, 추가 버튼은 노출하지 않는 **읽기 전용** 페이지로 구현합니다.
  - 아바타 이미지, 디스플레이 네임, 핸들(@아이디), Bio가 중앙 정렬된 미려한 프로필 영역을 렌더링합니다.
  - 사용자가 등록한 링크들을 깔끔하고 세련된 네오브루탈리즘/모던 스타일의 카드로 노출하고 클릭 시 새 탭으로 이동시킵니다.
  - 다크 모드 토글 기능을 제공하여 방문자 편의성을 높입니다.
- **네비게이션 연동**:
  - 관리자 대시보드(`app/links/page.tsx`)의 헤더 및 프로필 드롭다운 메뉴에 "내 페이지 보기(내 링크)" 메뉴를 추가하여 자신의 공개 페이지로 편리하게 이동할 수 있도록 연동합니다.

## 3. 작업 단계
1. **계획 및 태스크 설계**: 계획서(`implementation_plan.md`), 작업 목록(`task.md`), 진행 상황(`walkthrough.md`) 작성 및 업데이트 (진행 중)
2. **Firestore 서비스 함수 추가**: `lib/firestore-service.ts`에 `fetchProfileByDisplayName` 구현

4. **404 에러 페이지 구현**: `app/not-found.tsx` 생성
5. **관리 페이지 연동**: `app/links/page.tsx` 헤더 및 드롭다운 메뉴에 공개 페이지 이동 링크 추가
6. **빌드 검증**: `npm run build` 명령어로 타입 검사 및 컴파일 정합성 확인
